# 포트폴리오 갱신 장치

새 기록 파일을 `input/`에 넣고 한 번 실행하면, 포트폴리오의 숫자 칸과 능력별 문단 후보를 다시 만듭니다.
AI 서비스, 인터넷, 추가 설치가 필요 없습니다. 같은 입력이면 항상 같은 결과가 나옵니다.

## 돌리는 방법 (세 단계)

1. **Node.js 18 이상을 준비합니다.** `node -v`로 버전을 확인합니다.
2. **입력 파일을 `input/`에 넣습니다.** 아래 「입력 파일」 표를 따릅니다. 처음에는 들어 있는 파일을 그대로 써도 됩니다.
3. **이 폴더의 상위 폴더에서 실행합니다.**

   ```
   node engine/run.mjs
   ```

   결과는 `engine/output/`에 생깁니다. 상위 폴더에 `site/index.html`이 있으면 그 파일의 숫자 칸과 승인 문단 영역도 함께 바뀝니다.
   다른 위치의 사이트 파일을 바꾸려면 `node engine/run.mjs --site <index.html 경로>`로 실행합니다.

## 입력 파일 (`input/`)

| 파일 | 필수 | 내용 |
|---|---|---|
| `config.json` | 예 | 과정 이름, 시작일, 종료일, 전체 주 수 |
| `ritual-history-*.txt` | 예 | 리추얼 기록 내보내기 파일. 여러 개면 이름순으로 가장 마지막 파일을 씁니다. |
| `approved.json` | 아니오 | 사이트에 넣기로 승인한 후보 ID 목록. 예: `{ "approved": ["SR-2026-08-26"] }` |
| `attendance.csv` | 아니오 | 내 출석 기록. 열: `date,status` (status는 출석, 지각, 조퇴, 결석) |
| `submissions.csv` | 아니오 | 내 제출 현황. 열: `task,status,submitted_at` (status는 제출, 통과, 미제출) |

`attendance.csv`나 `submissions.csv`가 없으면 그 숫자는 "집계 중"으로 표시하고 기준일을 함께 적습니다.

## 결과 파일 (`output/`)

| 파일 | 내용 |
|---|---|
| `numbers.json` | 숫자 칸의 값, 출처, 설명 |
| `candidates.md` | 능력별 문단 후보. 후보마다 날짜와 근거가 붙어 있습니다. 승인한 후보는 `[x]`로 표시됩니다. |
| `candidates.json` | 같은 후보의 기계용 목록 |
| `site-numbers.html` | 사이트 숫자 칸에 들어가는 HTML |
| `site-approved.html` | 사이트 「기록에서 더 찾은 장면」에 들어가는 HTML |

## 후보를 승인하는 방법

1. `output/candidates.md`를 읽고 사이트에 넣을 후보의 ID(예: `IR-2026-10-14-P1`)를 고릅니다.
2. `input/approved.json`의 `approved` 배열에 ID를 적습니다.
3. 다시 실행합니다. 승인한 후보만 사이트에 들어갑니다.

## 같은 결과가 나오는 이유

- 기준일은 실행한 날이 아니라 리추얼 기록의 마지막 날짜입니다.
- 후보는 정해진 규칙(키워드, "못 했다" 다음 기록)으로만 고르고, ID 순서로 정렬합니다.
- AI 호출, 난수, 현재 시각을 쓰지 않습니다.

## 기록 원문에 대한 주의

`ritual-history-*.txt`는 내보내기 도구가 동료 이름을 "(이름 가림)"으로 바꾼 파일입니다. 도구가 이름과 같은 글자까지 가린 곳(예: "부(이름 가림)")은 장치가 "부분"으로 되돌려 표시합니다. 새 파일을 넣기 전에 본문에 남은 다른 사람의 이름이나 연락처가 없는지 직접 확인합니다.
